# Presentation dashboard

Real RADARSAT-2 change-candidate dashboard for the Myanmar footprint.
Data comes from the derived analysis pipeline only — no raw SAR archives are
stored or referenced in this directory.

## Run

```bash
cd frontend
npm install
npm run dev
```

Build and lint:

```bash
npm run lint
npm run build
```

## Data contract

`frontend/public/data/derived/` is the frontend contract. It is generated by:

```bash
python3 dashboard/scripts/build_contract.py \
  --derived /home/overlord/hackathon/rs2-analysis/data/derived/exploration_v2 \
  --out frontend/public/data
```

| File | Role |
| --- | --- |
| `contract.json` | Scene metadata, acquisition timeline, temporal-class taxonomy, counts, presentation path, imagery index |
| `candidate_regions.geojson` | 525 region polygons with area, dB change, terrain QA, priority score, temporal class, T4 status |
| `dashboard_metrics.json` | Summary metrics mirror (stable filename) |

`frontend/public/data/imagery/` holds the display renders (temporal RGB,
terrain QA mask, change maps, T1/T2/T3 quicklooks and crops).

## Temporal classes

| Class | Source `class_id` | Meaning |
| --- | --- | --- |
| `seasonal_transient` | 2 | Change returns toward the T1 level by T3 (valley-floor moisture cycle) |
| `persistent` | 1 | Change does not return toward T1 by T3; not yet validated by T4 |
| `t4_validated_persistent` | 1 + `t4_status=confirmed` | Persistent change that holds through T4 |
| `late_unclassified` | 3 | Change appearing only in the T2–T3 interval |

## Incorporating T4 validation

The frontend reads `temporal_class` and `t4_status` from the GeoJSON/JSON.
T4 results therefore land as a data update, not a code change:

1. Run `pipeline_4date.py` once the 2024-12-21 frames are downloaded and CRC-verified.
2. Adapt its evaluation output:

   ```bash
   python3 dashboard/scripts/t4_results_adapter.py \
     --pipeline-output /home/overlord/hackathon/rs2-analysis/data/derived/exploration_4date \
     --out /tmp/t4_results.json
   ```

3. Render the T4 comparison tile (analysis venv: rasterio/numpy/Pillow):

   ```bash
   python3 dashboard/scripts/render_t4_quicklook.py
   ```

4. Regenerate the contract:

   ```bash
   python3 dashboard/scripts/build_contract.py \
     --t4-results /tmp/t4_results.json \
     --out frontend/public/data
   ```

5. Reload the dashboard. Confirmed regions flip to `t4_validated_persistent`,
   the T4 comparison slot fills in, and the counts update.

No frontend source change is required for any of this.

## Smoke test

```bash
cd frontend
npm run dev -- --port 5199 --host 127.0.0.1 &
node smoke.mjs
```

Requires Playwright Chromium (`npx playwright install chromium`). The smoke test
asserts the map, filters, layers, inspector fields, image decoding and the live
T4-validated counts, then captures the presentation path as screenshots.

## Presentation path

Overview → seasonal river signal → filter to persistent anomalies → select
Region 2 → terrain QA → T4 validation. The `Presenter` panel drives map state
so the talk track is reproducible.

## Scientific limits

Candidates are unvalidated radar-change regions. Terrain, registration and
surface moisture may explain the signal. No cause classification and no
invented confidence percentage is shown anywhere in the UI.
