# RADARSAT-2 Backend Implementation Plan

> **For agentic workers:** Use SwarmForge specialists with separate file ownership and independent review. The user explicitly requested immediate parallel execution.

**Goal:** Build the acquisition, inspection, processing, and API backend for a real RADARSAT-2 change demonstration.

**Architecture:** Reproducible offline analysis publishes a local versioned bundle. A read-only API validates and exposes that bundle to the independently developed frontend.

**Tech stack:** Python 3.12, NumPy, SciPy, Rasterio/GDAL, Shapely, PyProj, FastAPI, pytest, official EODMS CLI. Product-specific SAR tooling remains conditional on actual inventory.

**Spec:** `docs/BACKEND-DESIGN.md`.

## Global constraints

- Human teammates own frontend files.
- Only the user performs credential-bearing EODMS actions. Credentials cannot enter argv, committed files, worker prompts, logs, or artifacts.
- No synthetic production or demo results. Synthetic test inputs must remain clearly identified test fixtures.
- No causal claims or invented confidence percentages.
- Independent review precedes implementation integration. Commits and remote persistence are verified.

## Review focus

- Missing or malformed input must yield an honest unavailable state.
- Metadata must distinguish footprint coordinates from raster georeferencing and sampled spacing from resolution.
- Nodata, complex/amplitude representations, and registration can create false changes.
- Preview paths and symlinks cannot expose files outside the result bundle.
- Teammate commits may advance main during every task.
